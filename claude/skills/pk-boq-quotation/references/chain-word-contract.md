## Word 合同：报价表嵌在条款里，按表格坐标取

合同文件带的报价表和独立报价单是两回事，**格式和语义都要换一套看法**。

**格式：走 `doc.tables`，不要转 Markdown 再解析。**

```python
import docx
d = docx.Document(path)
for t in d.tables:
    for row in t.rows:
        cells = [c.text.strip() for c in row.cells]
```

理由和 BOQ 那节的「列位是确定性信息」完全一样：单元格坐标是确定的，`anydoc`/`pandoc`
转 Markdown 会**把合并单元格摊平、把跨页续表拼错行**，再让 LLM 从 Markdown 里"看"回来
纯属自找错。`probe_source.py` 已经列出每张表的行列数与表头，并标出哪些是疑似价格表、
哪些是暂定金额类。

Markdown 转换只用在**正文条款**——付款条件、税费口径、价格调整条款、有效期。那部分是
给人读的上下文，不是取数的。

**语义：合同价不是报价。**

| | 报价单 | 合同报价表 |
|---|---|---|
| 价格性质 | 要约价，可议 | 已签约成交价 |
| `priceSource` | `quotation` | **`project`**（与分包 BOQ 同类，都是某个具体项目的成交价，不是市场要约价） |
| 日期 | 报价日期 | 合同签订日。找不到签订日才退回元数据，**退了就标 `uncertain`** |
| 单价是否独立成立 | 是 | **常附条件**："综合单价已包含XX"、"工程量增减超 10% 重新议价"、"材料涨跌幅调整" |

最后一行是合同链独有的风险：**单价从合同里抽出来入库，会把限定它的条款丢在门外**，
日后查价的人只看到一个光秃秃的数。所以合同链的填写铁律多两条，见下方表格末尾。

交回主会话时，除了 PDF 链要求的那些，还要说清：**用了哪几张表、每张表对应合同哪一节、
哪些表判定为暂定金额类而没取**。
