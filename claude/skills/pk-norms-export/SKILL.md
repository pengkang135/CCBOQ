# 定额明细导出

> **禁止用 Excel COM 处理表格**（BOQ 技能族硬规则）：不准启动 Excel 来读写、标记、插行、刷新或校验表格，`win32com` 和 COM 版 `excel` MCP 都不行 —— 它会抢占用户正开着的 Excel 实例、逼用户关文件等脚本、还比纯脚本慢。读值用 `fastexcel`，公式文本和保留格式改单元格用 `openpyxl`，插列/插行/搬 sheet/透视表这类结构操作走 zip+XML 层。这是**全局硬规则**（见 `~/.claude/CLAUDE.md` 的「Excel/AI 加速工具集」硬前置），不限 BOQ；BOQ 场景的具体替代做法见 [pk-boq/SKILL.md](../pk-boq/SKILL.md)。

从 SQLite 定额库按编号提取定额，一次导出**综合单价**和**人材机**两张表。两表用跨表公式连起来：人材机表填一次单价，综合单价表的所有单价自动算出。

技能不含任何项目信息，所有输入都由命令行给定。

## 运行

```bash
python scripts/export_norms.py --codes <codes.json> --db <定额库.sqlite> -o <输出.xlsx>
```

| 参数 | 说明 |
|------|------|
| `--codes` | 定额编号来源：pk-norms-match 的 `merge_summary.json`，或纯编号数组 JSON |
| `--db` | 定额库（企业定额 schema，有 `Norm` 表）。A~E 五册通用 |
| `-o` | 输出 xlsx（新建，只含两张表） |
| `--into` | 改为把两张表加进已有 xlsx（原有 sheet 不动，同名 sheet 覆盖） |
| `--rate` | 取哪个基价：`cny`（默认，`cons_Market` 人民币）/ `thb`（`cons_Price` 泰铢）。币种标注跟着走 |
| `--boq` | 提供工程量的清单 xlsx。不给则工程量与人材机数量留空，公式骨架仍在 |
| `--boq-sheet` | `--boq` 里的 sheet 名，默认 `UniqueBQ` |
| `--code-col` / `--qty-col` | `--boq` 里的定额编号列、工程量列**表头名**，默认 `Norm Code` / `Qty`。按列名定位，不依赖列号 |
| `--concrete-map` | 混凝土标号换算：`{定额编号: [{"grade":"50","qty":5676.0}, …]}`。给某个子目追加 `编号+c50`、名称 `…换C50` 的变体，消耗量里的混凝土/同等级砂浆换成该标号 |
| `--no-keep-original` | 换算时不保留原定额行（默认保留，便于对照与回退） |

带全部输入的完整调用：

```bash
python scripts/export_norms.py \
  --codes merge_summary.json \
  --db "E:/Code/Norms-AI/db/企业定额_A册_建筑装饰.sqlite" \
  --boq boq_classified.xlsx --qty-col Qty --rate cny \
  -o 综合单价表.xlsx
```

## 定额编号格式

`--codes` 两种都收：

- **完整编号** `A.01.02.001.BJ12.1-7` = 章节完整编码 + `.` + `Norm.norm_Code`。pk-norms-match 产出的就是这个，**无歧义，优先用**
- **裸子目编码** `BJ12.1-7`。A/C 册混有多套来源（BJ12/BJ21/PK），同一编码可能落在不同章节，此时取首个匹配并打 WARNING

## 输出格式

格式样张：[assets/quota_template.xlsx](assets/quota_template.xlsx)（脚本自身产出，改格式时同步更新）。

### 综合单价（66 列 A-BN）

| 列 | 内容 | 列 | 内容 |
|----|------|----|------|
| A | 序号 | G | 工程量 |
| B | 分类指标（分项工程名） | H | 单价 `=I+J+K` |
| C | 定额编号 | I | 人工 `=IFERROR(SUMPRODUCT(参考单价行, 消耗量行),0)` |
| D | 项目名称 | J | 材料（同上） |
| E | 单位 | K | 机械（同上） |
| F | 合价 `=G*H` | L-BN | 消耗量 ×55 |

第 1 行英文表头、第 2 行中文表头，冻结 **E3**。

样式规则（照 `assets/quota_template.xlsx`）：

- **E~BN 列水平居中、垂直靠上**；A 列居中，B~D 列左对齐垂直靠上
- **消耗量列（L~BN）的两行表头灰底填充**（theme0 tint -0.15），固定列表头无填充，用来标出消耗量区从哪开始
- **表头两行之间不画横线**：第 1 行无下框、第 2 行无上框，两行合成一个框
- **H~K 之间不画竖线**：单价/人工/材料/机械读作一个块（`单价 = 人工+材料+机械`）
- 列宽：A 6 / B 14 / C 18.22 / D 44.22 / **E（单位）5.11** / F、G、H 12 / I~K 默认 / L~BN 13

### 人材机（7 列 A-G）

| 列 | 内容 |
|----|------|
| A | 编号 |
| B | 名称（含规格：`预拌混凝土 C25`） |
| C | 单位 |
| D | 数量 = Σ(消耗量 × 工程量) |
| E | **除税单价** ← 定额库基价 |
| F | 合价 `=D*E` |
| G | 价格来源，如 `A册_建筑装饰 基价` |

第 1 行标题，第 2 行右上角 **F2/G2 = 币种：/`--currency`**，第 3 行表头，冻结 **A4**。

**全表无合并单元格**，表尾不加合计统计。三级分类标题只在 B 列写文字，整行铺底色，不合并。

### 两表联动

每个分项工程的**参考单价行**逐列写 `='人材机'!E{行号}`，指向该资源在人材机表的除税单价。链路：

```
人材机 E 列单价 → 综合单价 参考单价行(跨表引用) → I/J/K SUMPRODUCT（外层 `IFERROR(...,0)`，消耗量缺值时归 0 不报错） → H 单价 → F 合价
```

改一处单价，所有用到该资源的定额单价同步更新。脚本先建人材机表拿到行号，再写综合单价的引用，所以必须一次生成两表 —— 这是两个脚本合并成 `export_norms.py` 的原因。

### 层次与行分组（4 级，与 BOQ 一致）

| 层级 | 行类型 | 背景色 | 字体 |
|------|--------|--------|------|
| L1 | 章标题 `【】` | `#333F4F` 深蓝 | 微软雅黑 9pt 白色加粗 |
| L2 | 节标题 `《》` | `#D9E1F2` 浅蓝 | 微软雅黑 9pt `#1A1A1A` 加粗 |
| L3 | 分项工程 `{}` + 资源列头 | `#FBE5D6` 暖橙 | 微软雅黑 9pt `#1A1A1A` 加粗 |
| L4 | 参考单价行 | 无底色 | 微软雅黑 9pt 灰色 `#808080` |
| L4 | 数据行 / 分隔空白行 | 无底色 | 微软雅黑 9pt 常规 |

资源列头 7pt，英文表头 qty 列 8pt 加粗。人材机表同样是 `【】`/`《》`/`{}` 三级 + 数据行。

章/节/分项按章节编码**自然排序**，定额按编号自然排序（`BJ12.1-7` 在 `BJ12.1-14` 前，数字段按数值比）。同一分项工程内相同定额编号只出现一次。

## 混凝土标号换算（`--concrete-map`）

清单同一构件按标号分列（C30/C35/C50…），定额子目只按形状分、消耗量写死一个标号；用 `--concrete-map` 把标号差异补上：

- 映射由 `pk-norms-match/scripts/build_concrete_map.py` 从清单生成（欧标 `C50/60` 取第一个数 → `C50`），**必须喂换算前的表**（编号不带 `cXX` 后缀）。
- 每个变体：编号 `原编号+c{标号小写}`（如 `A.04.03.006.BJ21.5-10c50`）、名称 `原名+换C{标号}`（如 `矩形柱换C50`）、工程量用映射里的 `qty`（该标号的清单量）。
- 消耗量换两处：混凝土资源（`预拌混凝土/预拌水下混凝土/预拌豆石混凝土/商砼/混凝土 Cxx`，单位 m³，排除砌块/垫块/桩头等）→ `预拌混凝土 C{标号}`（保留 水下/豆石/商砼 限定词）；`同混凝土等级砂浆` → `同混凝土等级砂浆 C{标号}`。
- 目标标号在库里没有基价时，人材机新增该资源行、**单价留空**、价格来源写 `待询价`。
- 与原资源同标号的变体不生成；没有可换算混凝土/砂浆的子目不生变体。
- 原行与换算行并存（默认），综合单价里靠编号后缀区分。

## 消耗量单价

**本技能的重点是组价，不是套单价。** 基价已经固化在定额库每条定额子目里，直接取用，不去外部价格库比对多来源报价 —— 换基价就是换 `--db` 指向另一个库。

| `--rate` | 取值字段 | 币种标注 | 普工示例 |
|---------|---------|---------|---------|
| `cny`（默认） | `Consumption.cons_Market` | 人民币 | 138.6 |
| `thb` | `Consumption.cons_Price` | 泰铢 | 693 |

**币种由取哪个字段唯一决定**，同一处配置同时给出单价和币种标注，标注不可能和单价对不上。两列是同一基价的两种币值，固定 1 CNY = 5 THB（A/C/D 册实测比值恒为 5.0）。

- G 列写 `{库名} 基价`，库名从 `--db` 文件名去掉 `企业定额_` 前缀
- 同名同单位的资源在库里带了不同基价时取首个并 WARNING
- 取不到基价的写 `定额库无基价`（C 册 899 条、D 册 459 条无基价，属正常）

## 资源归并

归并键是 **(名称, 单位)**，名称 = `cons_Name + ' ' + cons_Standard`：

- 规格进名称：`预拌混凝土 C25` 与 `C30` 的基价不同（2730 vs 2870），合并会串价
- 单位进键：砂子在库里有 kg 和 m³ 两条记录，两个数量相加会得到一个没有单位的数

### 资源分类

三级 `【人工/主材/周转材/辅材/机械】` → `《种类》` → `{子类}`。分类体系是数据不是代码，两份配置分工：

| 文件 | 内容 |
|------|------|
| [config/resource_taxonomy.json](config/resource_taxonomy.json) | 分类树、排序、修正表、15 条按序匹配的关键词规则 |
| [config/resource_classification.json](config/resource_classification.json) | 资源名→分类的缓存（533+ 条），未命中时走规则并自动追加 |

改分类规则改 JSON，不动 [scripts/resource_taxonomy.py](scripts/resource_taxonomy.py)（96 行，只有加载和匹配逻辑）。「水/电」和「费用项」两条规则依赖名称本身，留在代码里。

综合单价表的资源列按 **人工→材料→机械** 排列（`Consumption.kind_ID` + 名称关键词判定），SUMPRODUCT 的三段范围就是这么切出来的。

## 定额库适配

五册（A 建筑装饰 / B 通用安装 / C 市政园林 / D 水运工程 / E 房屋修缮）都是企业定额 schema，`--db` 换路径即可，无需改脚本。章节名直接取 `chapter.chap_Name`，不做映射表。港口水工走 D 册。

## 上下游

```
pk-norms-match (merge_summary.json) → export_norms.py → 综合单价 + 人材机
```
