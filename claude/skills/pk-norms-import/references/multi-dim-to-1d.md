# 多维表转一维算法

定额表的核心数据结构挑战：将 2D 多维表头表格展开为 1D 长格式记录。

## 问题描述

定额书中的一个典型表格页：

```
                        地槽              地坑
                         无挡土板  有挡土板  无挡土板  有挡土板
定额编号  土壤类别        10018    10019    10020    10021
                        Ⅰ～Ⅱ    Ⅲ～Ⅳ    Ⅰ～Ⅱ    Ⅲ～Ⅳ
─────────────────────────────────────────────────────────
1  人工        工日   ...   10.37   21.38   12.96   26.57
2  板枋材      m³    ...      —       —     0.71    0.34
3  原木        m³    ...      —       —     0.45    0.22
4  其他材料    元    ...   24.00   24.00      —       —
5  其他材料    %     ...      —       —     0.91    0.95
6  基价        元    ... 1023.50 1987.30 1302.40 2456.80
```

这里有 3 个属性维度（开挖类型、支护方式、土壤类别）、4 个定额编号列、6 行费用项目。

### 目标输出

24 条 1D 记录（4 个定额编号 × 6 行费用项目）：

```
10018, 地槽, 无挡土板, Ⅰ～Ⅱ, 人工, 工日, ..., 10.37
10018, 地槽, 无挡土板, Ⅰ～Ⅱ, 板枋材, m³, ..., null
10018, 地槽, 无挡土板, Ⅰ～Ⅱ, 原木, m³, ..., null
10018, 地槽, 无挡土板, Ⅰ～Ⅱ, 其他材料, 元, ..., 24.00
10018, 地槽, 无挡土板, Ⅰ～Ⅱ, 其他材料, %, ..., null
10018, 地槽, 无挡土板, Ⅰ～Ⅱ, 基价, 元, ..., 1023.50
10019, 地槽, 无挡土板, Ⅲ～Ⅳ, 人工, 工日, ..., 21.38
...
10021, 地坑, 有挡土板, Ⅲ～Ⅳ, 基价, 元, ..., 2456.80
```

## 算法：列对齐 + 属性重建 + 一维展开

### Step 1: 列检测与对齐

输入是文本+坐标的行分组。找到"定额编号"行，提取所有 5 位数字作为列标识。

```
Row Y=83: [定额编号(x=151), 10018(x=313), 10019(x=379), 10020(x=445), 10021(x=511)]
                → code_columns = [
                    {code:"10018", x:313},
                    {code:"10019", x:379},
                    {code:"10020", x:445},
                    {code:"10021", x:511}
                  ]
```

### Step 2: 表头文本按列收集

对于表头区域（y 在 83 以上但在 subsection 行以下）的每个文本块，按 x 坐标分配到最近的列：

```
列1 (10018): [地槽, 无挡土板, 土壤类别, Ⅰ～Ⅱ]
列2 (10019): [地槽, 无挡土板, 土壤类别, Ⅲ～Ⅳ]    ← "土壤类别" 重复出现
列3 (10020): [地坑, 有挡土板, 土壤类别, Ⅰ～Ⅱ]
列4 (10021): [地坑, 有挡土板, 土壤类别, Ⅲ～Ⅳ]
```

### Step 3: 属性维度重建

AI 分析每列的 header_texts 序列，推断属性维度：

1. 找出在列间取值不同的文本 → 属性值
2. 找出在所有列相同的文本 → 属性名标签
3. 同一 y 层级的文本属于同一属性维度

```
属性1 (y=97):  地槽, 地槽, 地坑, 地坑          → 开挖类型
属性2 (y=111): 无挡土板, 无挡土板, 有挡土板, 有挡土板 → 支护方式
属性3 (y=139): Ⅰ～Ⅱ, Ⅲ～Ⅳ, Ⅰ～Ⅱ, Ⅲ～Ⅳ    → 土壤类别
```

### Step 4: 数据行解析

每行费用项目（序号 + 名称 + 单位 + 代码 + 各列数值）：

```python
data_rows = [
    {seq:1, name:"人工", unit:"工日", code:"192000010001",
     values: {"10018":10.37, "10019":21.38, "10020":12.96, "10021":26.57}},
    {seq:2, name:"板枋材", unit:"m³", code:"190503002020",
     values: {"10018":None, "10019":None, "10020":0.71, "10021":0.34}},
    ...
]
```

数值按 x 坐标匹配到最近的定额编号列（tolerance 100px）。

### Step 5: 一维展开

```python
items = []
for row in data_rows:
    for j, code_col in enumerate(code_columns):
        code = code_col["code"]
        item = {
            "quota_code": code,
            "cost_item": row["name"],
            "cost_item_unit": row["unit"],
            "code": row["code"],
            "amount": row["values"].get(code),
        }
        for attr_dim in attr_dimensions:
            item[f"attr_{attr_dim['name']}"] = attr_dim["values"][j]
        items.append(item)
```

## 边界情况

### 同名费用项目

"其他材料"出现两次，分别为"元"和"%"单位。展开时费用项目名改为"其他材料(元)"和"其他材料(%)"。

```python
def disambiguate_cost_items(data_rows, code_columns):
    seen = {}
    result = []
    for row in data_rows:
        key = row["name"]
        if key in seen:
            disambig = f"{key}({row['unit']})"
        else:
            disambig = key
        seen[key] = seen.get(key, 0) + 1
        result.append({**row, "disambiguated_name": disambig})
    return result
```

### 跨列合并的标题

某些表头文本跨越多列（如"地槽"在 10018 和 10019 上方跨两列）。算法通过比较 x 范围自动检测——文本的 x 如果在两列的中心附近，标记为跨列。

### 续表

续表页只有数据行，没有表头。属性维度和费用项目从首页继承。

### 超4个属性维度

DB schema 只支持 4 个属性维度（attr_level1~4）。如果有更多维度，前 4 个存入独立列，完整信息保留在 quota_table.header_json 中。

### 空列（定额编号未分配）

某些列位置有数值但无对应定额编号（编辑错误或特例），此时为该列生成 `quota_code = None` 记录，标记为需要人工复核。
