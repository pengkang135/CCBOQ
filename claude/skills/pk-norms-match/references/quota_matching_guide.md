# BOQ 套定额匹配经验总结

> 2026-05-06 | 经过三轮迭代优化，匹配率从 94.7%（大量误匹配）降至 13.7%（较可靠）

## 核心匹配公式

```
final_score = jaccard
            - 0.12 × non_overlap_count       (非重叠概念惩罚)
            - 0.15                           (分部上下文完全不匹配时)
            + 0.03/0.06/0.09                 (编码层级深度 1/2/3+)
            + 0.05                           (精确单位匹配)
            ─────────────────────────
            阈值 ≥ 0.30 → 匹配成功
```

Jaccard 本身还会被通用概念惩罚（×0.5）：当交集概念全部属于混凝土/drainage 等通用概念时触发。

## 关键发现与修复

### 1. 标点符号导致英文分词断裂

**现象**：`"... pile, Type A"` 中 `text.split()` 产生 `"pile,"` 而非 `"pile"`，导致多词 key `"steel pile"` 匹配失败。

**根因**：`extract_concepts` 部分匹配用 `text.lower().split()` 计算 `text_words`，未清洗标点。而 `_tokenize_en` 已用 `re.sub(r'[^\w\s/]', ' ', text)` 清洗过。

**修复**：在部分匹配中也做 `re.sub(r'[^\w\s/]', ' ', text.lower())` 清洗。

**教训**：英文文本的清洗逻辑必须在 token 提取和文本字面量两处保持一致。

### 2. 中文文本中英文字母大小写

**现象**：`"PVD塑料排水板"` 中 3-gram 产生 `"PVD"` 但概念键是 `"pvd"`（小写），大小写不匹配。

**根因**：`_tokenize_cn` 不做 lower()，而所有概念键都小写存储。

**修复**：`_tokenize_cn` 开头加 `text = text.lower()`。

**教训**：中英混合文本的 token 化必须先统一大小写。

### 3. 通用概念（drainage、concrete）导致跨专业误匹配

**现象**：PVD 排水板和排水管共享 `"drainage"` 概念，导致互匹。

**修复**：将 `"drainage"` 所在的概念组加入 `_GENERIC_CONCEPT_GROUPS`，当交集仅为此类通用概念时 Jaccard 减半。

**教训**：需要区分「锚定概念」（如 PVD、钢管桩、护舷）和「通用概念」（如 混凝土、排水）。仅有通用概念重叠不足以判定匹配。

**注意事项**：`_GENERIC_CONCEPT_GROUPS` 必须精确匹配目标集合，不能用 `any(kw in s)` 遍历（会误伤包含该词的特定概念组）。

### 4. 分部/子分部标题上下文权重

**现象**：`"Fender numbers"` 在 `"Quay Linemarking"`（标记/涂装）分部下，仍匹配到「护舷」定额。

**修复**：
- 读取 BOQ 时跟踪 `【Class】→ 《Section》→ {Sub-section}` 层次
- 提取分部标题的概念集，合并到 BOQ 条目的概念中（稀释 Jaccard）
- 当定额概念集与分部概念集无任何交集时，施加 −0.15 惩罚

**教训**：BOQ 的结构层次携带了重要的专业归属信息，不能忽略。

### 5. 概念组设计原则

**短键覆盖**：如只设 `"混凝土板桩"`（5字），2-gram 只能切出 `"混凝" "凝土" "土板" "板桩"`。必须同时加 `"板桩"` 作为短键，否则无法匹配 2-gram token。

**避免模糊词**：
- `"removal"`（拆除/拆除模板/拆除支撑）→ 从拆概念组移除
- `"fill"`（回填/混凝土填充/充填）→ 从回填概念组移除

**多词键设计**：优先用 `"steel pile"` 多词键（非连续匹配容错），而非 `"steel"` 单词键（太短被跳过）。

### 6. 参数平衡经验

| 参数 | 值 | 说明 |
|------|-----|------|
| min_score | 0.30 | 低于 0.30 误匹配暴增，高于 0.35 漏匹配过多 |
| non_overlap 惩罚 | 0.12/个 | 0.10 太松（≠概念得不到有效惩罚），0.15 可能过严 |
| 分部上下文不匹配 | −0.15 | 定额与分部主题完全不符时 |
| 编码深度加成 | +0.03~0.09 | 引导同分部内匹配优先 |
| 通用概念 Jaccard 折扣 | ×0.5 | 只有混凝土/drainage 重叠时 |
| 单位精确匹配 | +0.05 | 同单位小加分 |

### 7. 数据质量问题

- `"Cocrete"`（拼写错误）→ 无法匹配 concrete 概念 → 该条目漏匹配
- `"Frabrication"`（拼写错误）→ 不影响匹配（因概念键匹配的是 steel/pile 等核心词）
- Φ 符号在不同编码下可能变成 `"��"` → 建议用 `mm` 单位识别管径
