# pk-boq-review 设计：大改清单的 HTML 审阅模式

日期：2026-10-06
状态：待用户审阅

## 目标

大改 BOQ 清单前，先生成一份 1:1 模拟清单格式的 HTML 审阅稿。用户在浏览器里直接改单元格、逐行写审阅意见，保存后，AI 在下一轮会话读回这份文件，拿到完整准确的修改清单与意见，据此改出新版本 Excel。

成功标准：
- 任意一份 BOQ xlsx，一条命令生成审阅稿，放在源文件旁边。
- 用户保存后，新会话的 AI 运行一条命令即可读出全部修改（行、编号、列、原值、新值）和全部意见，无遗漏、无假修改。
- 源文件在审阅期间被改动时，读回能发现并提示。

## 已定决策

| 项 | 决定 |
|---|---|
| 显示列 | 只显示编号、英文描述、中文描述、单位，最右侧加"审阅意见"列；不显示工程量列（只有这几列决定清单内容） |
| 修改记录载体 | 路线 A：保存时把记录写成结构化数据嵌在 HTML 内，读回脚本读这段数据 |
| 保存位置 | 浏览器"另存为"对话框（File System Access API），默认文件名与源文件对应，用户第一次选到清单所在文件夹，以后覆盖原审阅稿；不支持该 API 的浏览器退回为下载 |
| 回写 | 不做自动回写。AI 读回清单后按知识库「工作/BOQ 编制约定」的版本与标记约定改出新版本 |
| 技能位置 | 新子技能 `pk-boq-review`，挂在 `pk-boq` 技能族路由下 |

## 1. 组成

```
pk-boq-review/
├── SKILL.md              触发词、三步循环、命令用法
└── scripts/
    ├── review_html.py    xlsx → 审阅稿 HTML（也提供 render() 供重构脚本复用）
    └── review_read.py    审阅稿 HTML → 修改清单 + 意见清单 + 源文件校验
```

模板放 `albedo-cfg/claude/skills/pk-boq-review/`，同步到 `~/.claude/skills/pk-boq-review/`。`pk-boq` 路由表加一行。`pk-boq` 的 albedo-cfg 副本与运行副本已不一致，路由表两处分别做最小修改，不整份同步。

## 2. 生成：review_html.py

命令：

```
python review_html.py <xlsx> [--sheet 名称] [--header-row N] [--cols 编号,英文,中文,单位] [--out 路径]
```

- 读取：xlsx 可能正被 Excel 打开，用全共享方式读出字节（`CreateFileW` + `FILE_SHARE_READ|WRITE|DELETE`），再交给 openpyxl。需要单元格底色与字体（删除线、红字）判定行类型和修订标记，故此处用 openpyxl 而非 fastexcel；只读，不保存。
- 工作表：默认取第一个含可识别表头的工作表；`--sheet` 指定。
- 表头识别：扫描前 30 行，找同时含"编号"（No./Code/Item/编号）、"描述"（Description）、"单位"（Unit/单位）的行；中文描述列识别"中文"二字。识别不到时报错并提示用 `--header-row`、`--cols` 指定。表头行本身不进表体。
- 行类型：按底色判定——333F4F 章、D9E1F2 节、FBE5D6 小标题；底色缺失时按文字【】《》{} 兜底。
- 修订标记：C6EFCE 新增、FFFF00 修改、红字或删除线为删除，原样显示。其余底色原样保留。
- 输出：默认 `<源文件名去扩展名>_审阅稿.html`，与源文件同目录。
- 嵌入元数据（写进 `review-data` 数据块的 `meta`）：源文件绝对路径、工作表名、表头行号、列映射、源文件修改时间与字节数、生成时间、工具版本。

## 3. 审阅页面

- 列：行号（只读，对应 Excel 行号）、编号、英文描述、中文描述、单位、审阅意见（最右）。行号常显。
- 表格区为独立滚动区域，表头固定（`position:sticky; top:0`），列宽可拖拽（相邻两列此消彼长），列宽存浏览器本地。
- 工具栏 4 个按钮：保存、复制变更清单、重置列宽、清除全部编辑。计数器分别显示"修改 N 处 / 意见 M 条"。
- 改过的单元格橙框标记；写了意见的行在行号格加标记。
- 编辑过程自动暂存到浏览器本地存储，键由源文件路径 + 源文件修改时间生成，不同版本互不干扰。
- 打开审阅稿时：先按 `review-data` 中已保存的记录还原修改与意见，再叠加本地暂存中尚未保存的编辑。
- 保存：先把当前全部修改与意见写入 `review-data` 的 `review` 部分（含保存时间），再弹出"另存为"对话框，默认文件名为当前审阅稿文件名；不支持时退回下载。
- 比较规则：判断"是否修改"前统一规范化文本——`\r\n` 转 `\n`、不换行空格转普通空格、去掉首尾空白——避免浏览器带来的假修改。

## 4. 数据块格式

```html
<script type="application/json" id="review-data">
{
  "meta": {"source": "...xlsx", "sheet": "CIFC BQ", "header_row": 3,
           "cols": {"code": "B", "en": "C", "zh": "D", "unit": "E"},
           "source_mtime": "2026-10-06T14:13:00", "source_size": 123456,
           "generated_at": "...", "tool": "pk-boq-review 1.0"},
  "review": {"saved_at": "...",
             "edits": [{"row": 6, "code": "A.01.01.001", "col": "zh", "old": "...", "new": "..."}],
             "comments": [{"row": 12, "code": "A.01.02.003", "text": "删除"}]}
}
</script>
```

`code` 取该行当前（修改前）的编号，供读回核对。

## 5. 读回：review_read.py

命令：

```
python review_read.py <审阅稿.html> [--json 输出路径]
```

- 读 `review-data`；数据块缺失（旧格式审阅稿）时退回比对 `data-orig` 与单元格文字。
- 校验源文件：不存在、修改时间或字节数与 `meta` 不同，均在输出顶部给出警告，提示"审阅期间源文件已变动，行号可能错位"，并按编号重新定位各行，列出编号对不上的条目。
- 输出（终端，Markdown）：
  1. 源文件信息与校验结果；
  2. 修改清单表：行 | 编号 | 列 | 原值 | 新值；
  3. 意见清单表：行 | 编号 | 当前描述（中文，截断）| 意见；
  4. 汇总：修改 N 处、意见 M 条。
- `--json`：同样内容写成 JSON，供脚本处理。
- 无任何修改与意见时明确输出"审阅稿无修改"。

## 6. 技能工作流（SKILL.md）

1. 生成：用户要大改清单 → AI 跑 `review_html.py` 生成审阅稿，告诉用户路径。
2. 审阅：用户在 Edge/Chrome 打开、修改、写意见、保存（第一次选到清单所在文件夹）。
3. 读回与改版：AI 跑 `review_read.py`；校验有警告先问用户；按知识库「工作/BOQ 编制约定」复制 vN → vN.1，文字修改直接写入并标黄，删行按红字删除线，新增标绿；结构性意见（插行、移动、调层级）走 zip/XML 层（参考运行副本 `~/.claude/skills/pk-boq/scripts/xlsx_rowops.py`，albedo-cfg 模板里没有这个文件），不启动 Excel；改完再生成 vN.1 的审阅稿供下一轮。
4. 触发词：审阅稿、审阅模式、HTML 预览清单、大改清单、先在 HTML 上改、读审阅稿。

## 7. 与现有 CIFC 脚本的关系

`BOQ Prep\Ref\Structure\temp\scripts\boq_html.py` 及调用它的重构脚本保持不动。`review_html.py` 提供同样形参的 `render(rows, ...)`，CIFC 后续版本可改为调用技能内的版本，本次不迁移。

## 8. 测试

- 用 openpyxl 造一份小型夹具 xlsx（表头在第 3 行、含章/节/小标题底色、一条黄色修改行、一条红字删除行），断言生成的 HTML：表体不含表头行、行类型与标记正确、`meta` 正确。
- 在夹具 HTML 上写入模拟的 `review-data`（2 处修改、1 条意见），断言 `review_read.py` 输出逐项一致；再改动夹具 xlsx 的修改时间，断言出现源文件变动警告。
- 浏览器端到端：用 CIFC `CIFC BOQ_v4.1.xlsx` 生成审阅稿，经本机临时 HTTP 服务在内置浏览器中打开，脚本模拟改两格、写一条意见、触发保存逻辑（写数据块部分），读回核对；检查表头吸顶与控制台无报错。
- 文件保存对话框需真人操作，留给用户在 Edge 里实测一次。

## 不在范围
