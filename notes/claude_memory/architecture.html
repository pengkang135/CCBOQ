Claude Code 记忆与进化架构

外部记忆管道 + 离线进化引擎 — 不修改 Claude Code，补上跨会话记忆与技能进化能力

IDE 主场景 16 MCP 服务器 多 Vault 无上限记忆 跨会话模式发现 离线技能提炼

1 数据流详解

IDE 模式采集

Claude Code 自动增量写入

  • 1 每轮回复完成 → 追加写入 ~/.claude/projects/{id}.jsonl
  • 2 完整 tool_use / tool_result / text_delta / result 序列
  • 3 用户关闭 IDE → 数据已落盘 (进程退出前)
  • 4 会话归档流程 → staging/cc-{id}.json (可选)
  • 5 cron 30min 扫描 → pipeline 摄入

记忆管道处理

6 阶段标准化流水线

  • fetch 扫描 JSONL + staging → 提取消息
  • canonicalize 按 source 类型分发 → Threaded JSON
  • chunk SHA-256 幂等去重 → 分块
  • store 写入 Librarian vault
  • bucket 累积阈值: 10msg / 5000token / 60min
  • evaluate DeepSeek LLM 提取结构化记忆

上下文注入 (IDE)

SessionStart Hook 触发

  • 1 IDE 启动 Claude → SessionStart Hook 触发
  • 2 context/resolver.py 获取 cwd
  • 3 查 Librarian: 该目录最近 10 条记忆
  • 4 取 top 2 记忆 + top 1 技能 (硬上限 200 token)
  • 5 写入 SESSION_CONTEXT.md
  • 6 CLAUDE.md 引用 → Claude 自动阅读

微信薄桥接 (可选)

辅助通道 · 不阉割能力

  • 收 wx-cli 读取微信消息 → 提取文本
  • 调 claude.exe --bare -p --output-format stream-json
  • 解 解析 stream-json → 文本块推微信
  • 录 旁路写 tool event JSONL (fire-and-forget)
  • 注 调 context/resolver.py → system prompt 注入

3 各系统定位与取舍

这套方案

Claude-as-Engine + 外部进化
  • 定位: 给 Claude Code 补记忆和进化, 不改执行层
  • 核心取舍: 放弃实时干预, 换取跨会话模式发现 + MCP 生态深度
  • 适用场景: 日常 IDE 使用为主, 需要知识积累和技能提炼的长期用户
  • 不需要 多模型路由, 不需要子代理并行, 不需要远程执行后端
  • 最弱项: 无法实时介入, 无法"这次踩坑这次学会"
  • 最强项: 工具生态即时可用, 跨会话知识无限积累

Hermes (标准版)

全栈 Agent 操作系统
  • 定位: 从零构建的自主 agent, 拥有完整控制权
  • 核心取舍: 自写一切 (loop/工具/安全/训练), 换取最大灵活性和控制力
  • 适用场景: 需要精细控制迭代预算, 多模型降本, 多后端部署的企业级场景
  • 需要 维护 10,700 行 agent loop, 写 40+ Python handler, 跑 GRPO RL 训练
  • 最弱项: 工具生态需自己建设, 记忆容量有限, 无跨会话视角
  • 最强项: 实时干预 + 多模型路由 + 子代理并行 + 模型训练闭环

OpenClaw (已弃用)

桌面 AI 伴侣 + 消息通道
  • 定位: 微信/Telegram 通道 + Claude CLI 后端 + 记忆系统
  • 核心取舍: 重人设和消息体验, 轻工具执行能力
  • 适用场景: 聊天陪伴 + 轻量任务, 不适合复杂工程工作
  • 致命问题: gateway 覆盖 MCP 发现 → 16 工具变 3 个; 人设吃掉大量上下文
  • 可复用部分: memory-pipeline, Librarian, wx-cli, dreaming 子系统
  • 遗产价值: 记忆基础设施是这套方案的直接基础

4 关键设计决策: 为什么这么选

造价工程师的典型工作流

微信收文件 → OCR 识别扫描件 → PDF/Markdown 转换标书 → Excel 造价表分析 → 生成差异报告 → 归档知识到 Librarian

这套方案的每一项设计决策都服务于这个工作流: MCP 生态 让工具链开箱即用 (不需要写 Python handler); 多 Vault 承载定额标准/历史项目/价格信息 (2,200 字的 MEMORY.md 根本不够); 离线进化 从重复的 Excel 操作中发现模式 (Hermes 的 per-session 记忆看不到); 全部本地 保证造价数据不出机器; 微信薄桥接 作为辅助通道 (不阉割能力)。

1. 不拥有 Agent Loop

是约束, 不是设计选择

如果 Claude Code 暴露 mid-turn hook, 方案会立刻加入实时 nudge。

为什么还是选它: Claude Code 的执行质量 (>Hermes 任意单模型) + 16 MCP 的开箱即用能力, 远大于"不能实时介入"的损失。外部观察的跨会话视角是副产品, 但成了独特优势。

2. 从 OpenClaw 继承而非重写

memory-pipeline + Librarian 是成熟的

OpenClaw 虽然执行层有致命缺陷 (MCP 阉割, 上下文膨胀), 但记忆基础设施是扎实的。

继承的: pipeline (fetch/canonicalize/chunk/write/bucket-seal/evaluate), Librarian (FTS5+向量+decay), dreaming, wx-cli。
丢弃的: gateway (覆盖 MCP), bootstrap 人设 (吃 token), agent 运行时。

3. 进化是离线批量的 (接受这个天花板)

换来了 Hermes 做不到的事

实时进化需要 agent loop — Hermes 的 nudge engine 就是干这个的。没有 loop 就只能离线。

但 Hermes 的 per-session 记忆看不见跨会话模式。外部观察者能看到"20 次 Excel 操作有 15 次在修 VLOOKUP" — 这是架构的副产品, 也是独特优势。

4. MCP 生态是执行力根基

不写工具, 接入生态

Hermes 需要为每个新能力写 Python handler。这套方案接入 MCP — 每个新 MCP 服务器自动成为系统能力。

rapid-ocr, pdf2md, pandoc, excel, playwright, docker, mongodb, ssh... 16 个服务器覆盖开发全流程, 零额外开发成本。
